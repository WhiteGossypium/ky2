# Граф зависимостей пакетов npm

Инструмент визуализации графа зависимостей для менеджера пакетов npm.
Готовые менеджеры пакетов и библиотеки для получения зависимостей
не используются: только стандартная библиотека Python.

Текущее состояние: **этап 4** — режим обратных зависимостей.

## 1. Общее описание

Все параметры пользователь задаёт в конфигурационном файле формата CSV.
Программа читает файл, проверяет каждый параметр, строит граф зависимостей
пакета с учётом транзитивности (зависимости зависимостей) и печатает его.
Источник данных — реестр npm или файл тестового репозитория.
В режиме `reverse` программа печатает обратные зависимости: пакеты,
которые зависят от заданного.
При ошибке программа печатает сообщение `error: ...` и завершается
с кодом 1.

### Откуда берутся данные

Реестр npm отдаёт по адресу `<repository>/<имя пакета>` документ JSON
со всеми версиями пакета. Программа запрашивает сокращённый документ
(заголовок `Accept: application/vnd.npm.install-v1+json`), находит в нём
заданную версию и читает поле `dependencies`: имя зависимости и диапазон
допустимых версий, например `accepts ~1.3.8`. В имени с областью
(`@types/node`) косая черта кодируется: `@types%2Fnode`. Скачивание —
стандартный модуль `urllib`, разбор — стандартный модуль `json`.

Поле `devDependencies` (нужно только разработчикам пакета) не читается.
Необязательные зависимости npm при публикации сам добавляет
в `dependencies`, поэтому они тоже видны.

### Выбор версии зависимости

У зависимости указан не номер, а диапазон. Программа сама разбирает
диапазоны (`src/semver.py`) и выбирает версию так же, как npm:
если метка `latest` подходит под диапазон, берётся она, иначе —
новейшая подходящая версия. Поддерживаются `1.2.3`, `^1.2.0`, `~1.3.8`,
`1.x`, `*`, `>=1.0.0 <2`, `1.0.0 - 2.0.0`, варианты через `||`, метки
(`latest`, `next`) и псевдонимы `npm:имя@диапазон`. Предварительные
версии (`2.0.0-beta.1`) подходят, только если названы в диапазоне явно.
Зависимости из git, по URL или из локальной папки не поддерживаются:
такой пакет попадает в список `not loaded`.

### Построение графа

Вершина графа — `имя@версия` (в тестовом режиме — просто имя).
Граф строится алгоритмом обхода в глубину (DFS) **с рекурсией**:
функция `visit` раскрывает пакет и вызывает сама себя для каждой
зависимости. Путь от начального пакета до текущего хранится в списке:

- зависимость уже есть в пути — найден цикл, он запоминается,
  рекурсия по этой зависимости не идёт;
- зависимость уже раскрыта раньше — ребро добавляется, второй раз
  пакет не раскрывается;
- имя содержит подстроку `filter` — пакет не учитывается вместе
  со всей своей веткой, версия для него даже не подбирается;
- данные пакета не загрузились — пакет остаётся в графе с пометкой
  `not loaded`, обход продолжается.

### Тестовый репозиторий

При `test_mode,true` параметр `repository` — путь к текстовому файлу.
Пакеты называются большими латинскими буквами. Версия не используется.

```text
# комментарий
A: B, C
B: D
C: D
D:
```

| Файл | Случай |
|---|---|
| `test_repos/simple.txt` | две прямые зависимости |
| `test_repos/diamond.txt` | ромб: общая зависимость раскрывается один раз |
| `test_repos/chain.txt` | длинная цепочка транзитивных зависимостей |
| `test_repos/cycle.txt` | два цикла |
| `test_repos/self_loop.txt` | пакет зависит сам от себя |
| `test_repos/filter.txt` | фильтр `XY` убирает ветки `XY` и `XYZ` |
| `test_repos/undescribed.txt` | зависимость не описана в файле |
| `test_repos/broken.txt` | ошибка формата |

Для каждого файла есть настройки `configs/test_*.csv`.

### Обратные зависимости

Обратные зависимости пакета — пакеты, которые от него зависят,
напрямую или через другие пакеты. Программа переворачивает все рёбра
тестового репозитория (`reverse_index`: «кто от меня зависит») и обходит
перевёрнутый граф **тем же** рекурсивным DFS. Фильтр и поиск циклов
работают так же.

Режим работает только с тестовым репозиторием. Чтобы найти, кто
зависит от пакета npm, нужно просмотреть все пакеты реестра (их
миллионы), а списка зависящих пакетов реестр не отдаёт. Поэтому
`reverse,true` без `test_mode,true` — ошибка настроек.

| Настройки | Случай |
|---|---|
| `configs/reverse_diamond.csv` | от `D` зависят `B`, `C` и через них `A` |
| `configs/reverse_chain.csv` | вся цепочка до начала |
| `configs/reverse_cycle.csv` | циклы в обратном графе |
| `configs/reverse_filter.csv` | все зависящие пакеты убраны фильтром |
| `configs/reverse_root.csv` | от корневого пакета никто не зависит |
| `configs/reverse_undescribed.csv` | пакет без своей строки в файле |

## 2. Настройки

Файл CSV. Первая строка — заголовок `parameter,value`, дальше по одной
строке на параметр. Разделитель — запятая или точка с запятой (так
сохраняет Excel с русскими настройками). Пустые строки пропускаются.

```csv
parameter,value
package,express
repository,https://registry.npmjs.org
test_mode,false
version,4.18.2
filter,
```

| Параметр | Значение | Ошибки |
|---|---|---|
| `package` | имя анализируемого пакета npm, например `express` или `@types/node`; в тестовом режиме — большие латинские буквы | пустое имя, недопустимые символы, длиннее 214 символов, маленькие буквы в тестовом режиме |
| `repository` | URL реестра npm; в тестовом режиме — путь к файлу тестового репозитория | пустое значение, не http(s)-адрес, файла нет |
| `test_mode` | режим тестового репозитория: `true` или `false` | любое другое значение |
| `version` | точная версия пакета, например `4.18.2`; в тестовом режиме может быть пустой | пустая версия, версия не вида `1.2.3` |
| `filter` | подстрока: пакеты, в имени которых она есть, не учитываются; может быть пустой | пробелы внутри, подстрока исключает сам анализируемый пакет |
| `reverse` | необязательный: `true` — вывести обратные зависимости; по умолчанию `false` | не `true`/`false`; `true` без тестового режима |

Ошибки самого файла: файла нет, файл пустой, неверный заголовок,
в строке не 2 столбца, неизвестный параметр, параметр повторяется,
не хватает параметров.

## 3. Функции

| Модуль | Функция | Назначение |
|---|---|---|
| `src/main.py` | `run` | читает настройки, строит граф, печатает отчёт |
| | `make_source`, `graph_for` | выбирают источник и строят граф |
| `src/graph.py` | `build_graph` | строит граф от начальной вершины |
| | `DepthFirstSearch.visit` | рекурсивный обход в глубину |
| | `DepthFirstSearch.kept_children` | зависимости вершины без исключённых фильтром |
| | `remember_cycle` | запоминает найденный цикл |
| | `Graph` | вершины, рёбра, циклы, ошибки загрузки, исключённые имена |
| `src/sources.py` | `NpmSource` | зависимости из реестра, вершина `имя@версия` |
| | `FileSource` | зависимости из тестового репозитория |
| | `reverse_index` | переворачивает рёбра графа |
| | `ReverseFileSource` | соседи пакета — пакеты, которые от него зависят |
| `src/file_repository.py` | `parse_repository`, `load_repository` | читают файл тестового репозитория |
| `src/semver.py` | `parse_version`, `parse_range`, `satisfies` | разбирают версии и диапазоны |
| | `choose_version` | выбирает версию под диапазон, как npm |
| `src/report.py` | `graph_lines` | текстовый отчёт о графе |
| | `reverse_lines` | отчёт об обратных зависимостях |
| `src/settings.py` | `read_rows` | читает строки CSV, выбирает разделитель |
| | `check_header`, `collect_values`, `check_complete` | проверяют структуру файла |
| | `check_package`, `check_repository`, `check_test_mode`, `check_version`, `check_filter` | проверяют по одному параметру |
| | `load_settings` | возвращает объект `Settings` с проверенными значениями |
| `src/npm_registry.py` | `package_url` | строит адрес документа пакета |
| | `read_url`, `download_document` | скачивают и проверяют документ JSON |
| | `NpmRegistry.manifest` | описание заданной версии; документ скачивается один раз |
| | `NpmRegistry.direct_dependencies` | прямые зависимости: пары имя и диапазон |
| | `NpmRegistry.resolve` | подбирает версию зависимости под диапазон |
| `src/errors.py` | `ToolError` | ошибка, которую видит пользователь |

## 4. Сборка, запуск и тесты

Сборка не нужна. Нужен Python 3.9 или новее.

| Действие | Команда |
|---|---|
| Запуск с `config.csv` | `run.bat` |
| Запуск с другим файлом | `run.bat configs\chalk.csv` |
| Тесты | `test.bat` |
| Ошибки настроек | `examples\demo_settings.bat` |
| Ошибки реестра (нужен интернет) | `examples\demo_direct.bat` |
| Прямые зависимости (нужен интернет) | `examples\demo_settings.bat` |
| Графы | `examples\demo_graph.bat` |
| Обратные зависимости | `examples\demo_reverse.bat` |

## 5. Примеры использования

```text
> run.bat configs\chalk.csv
root: chalk@4.1.2
packages: 6, edges: 5
chalk@4.1.2 -> ansi-styles@4.3.0, supports-color@7.2.0
ansi-styles@4.3.0 -> color-convert@2.0.1
color-convert@2.0.1 -> color-name@1.1.4
color-name@1.1.4 -> (none)
supports-color@7.2.0 -> has-flag@4.0.0
has-flag@4.0.0 -> (none)

> run.bat configs\test_cycle.csv
root: A
packages: 5, edges: 6
A -> B
B -> C
C -> A, D
D -> C, E
E -> (none)
cycle: A -> B -> C -> A
cycle: C -> D -> C

> run.bat configs\test_filter.csv
root: A
packages: 3, edges: 2
A -> B
B -> C
C -> (none)
excluded by filter: XY, XYZ

> run.bat configs\reverse_diamond.csv
reverse dependencies of D: 3
dependents: B, A, C
D <- B, C
B <- A
A <- (none)
C <- A

> run.bat configs\network_errors\no_such_version.csv
error: express has no version 99.0.0 (latest is 5.3.0)

> run.bat configs\errors\version_invalid.csv
error: version: '4.18' is not a version like 1.2.3
```

В папке `configs/errors` лежит по файлу на каждую ошибку настроек,
в `configs/network_errors` — ошибки реестра: нет пакета, нет версии,
нет связи.
