# Граф зависимостей пакетов npm

Инструмент визуализации графа зависимостей для менеджера пакетов npm.
Готовые менеджеры пакетов и библиотеки для получения зависимостей
не используются: только стандартная библиотека Python.

Текущее состояние: **этап 5** — визуализация на языке диаграмм Mermaid.

## 1. Общее описание

Все параметры пользователь задаёт в конфигурационном файле формата CSV.
Программа читает файл, проверяет каждый параметр, строит граф зависимостей
пакета с учётом транзитивности (зависимости зависимостей) и печатает его
описание на языке диаграмм Mermaid. Источник данных — реестр npm или файл
тестового репозитория. Если задан параметр `output`, описание сохраняется
в файл: `.mmd` — текст диаграммы, `.html` — страница, которая рисует
диаграмму в браузере. При ошибке программа печатает сообщение `error: ...`
и завершается с кодом 1.

### Откуда берутся данные

Реестр npm отдаёт по адресу `<repository>/<имя пакета>` документ JSON
со всеми версиями пакета. Программа запрашивает сокращённый документ
(заголовок `Accept: application/vnd.npm.install-v1+json`), находит в нём
заданную версию и читает поле `dependencies`: имя зависимости и диапазон
допустимых версий, например `accepts ~1.3.8`. В имени с областью
(`@types/node`) косая черта кодируется: `@types%2Fnode`. Скачивание —
стандартный модуль `urllib`, разбор — стандартный модуль `json`.

Поле `devDependencies` (нужно только разработчикам пакета) не читается.
Необязательные зависимости npm при публикации сам добавляет
в `dependencies`, поэтому они тоже видны. Поле `peerDependencies`
не читается (см. раздел 6).

### Выбор версии зависимости

У зависимости указан не номер, а диапазон. Программа сама разбирает
диапазоны (`src/semver.py`) и выбирает версию так же, как npm:
если метка `latest` подходит под диапазон, берётся она, иначе —
новейшая подходящая версия. Поддерживаются `1.2.3`, `^1.2.0`, `~1.3.8`,
`1.x`, `*`, `>=1.0.0 <2`, `1.0.0 - 2.0.0`, варианты через `||`, метки
(`latest`, `next`) и псевдонимы `npm:имя@диапазон`. Предварительные
версии (`2.0.0-beta.1`) подходят, только если названы в диапазоне явно.
Зависимости из git, по URL или из локальной папки не поддерживаются:
такой пакет попадает в граф с пометкой `not loaded`.

### Построение графа

Вершина графа — `имя@версия` (в тестовом режиме — просто имя).
Граф строится алгоритмом обхода в глубину (DFS) **с рекурсией**:
функция `visit` раскрывает пакет и вызывает сама себя для каждой
зависимости. Путь от начального пакета до текущего хранится в списке:

- зависимость уже есть в пути — найден цикл, он запоминается,
  рекурсия по этой зависимости не идёт;
- зависимость уже раскрыта раньше — ребро добавляется, второй раз
  пакет не раскрывается;
- имя содержит подстроку `filter` — пакет не учитывается вместе
  со всей своей веткой, версия для него даже не подбирается;
- данные пакета не загрузились — пакет остаётся в графе с пометкой
  `not loaded`, обход продолжается.

### Описание на языке Mermaid

```text
flowchart LR
%% root: A
%% packages: 5, edges: 6
%% cycle: A -> B -> C -> A
%% cycle: C -> D -> C
    n0["A"]
    n1["B"]
    n2["C"]
    n3["D"]
    n4["E"]
    n0 --> n1
    n1 --> n2
    n2 -. cycle .-> n0
    n2 --> n3
    n3 -. cycle .-> n2
    n3 --> n4
    classDef root fill:#cfe8ff,stroke:#1f6feb,stroke-width:2px
    classDef problem fill:#eeeeee,stroke:#999999,stroke-dasharray:4 3
    class n0 root
```

- `flowchart LR` — граф слева направо;
- `n0["A"]` — вершина: короткий номер и подпись `имя@версия`;
- `-->` — зависимость; `-. cycle .->` — ребро, замыкающее цикл (пунктир);
- строки `%%` — комментарии: итоги, циклы, ошибки, исключённые пакеты;
- корень выделен голубым, незагруженные пакеты — серым пунктиром.

Нарисовать диаграмму можно тремя способами: открыть файл `.html`
в браузере (страница берёт библиотеку Mermaid с cdn.jsdelivr.net, нужен
интернет), вставить текст на https://mermaid.live или в README на GitHub
(блок ` ```mermaid `).

## 2. Настройки

Файл CSV. Первая строка — заголовок `parameter,value`, дальше по одной
строке на параметр. Разделитель — запятая или точка с запятой (так
сохраняет Excel с русскими настройками). Пустые строки пропускаются.
Файл по умолчанию — `config.csv` в текущей папке.

```csv
parameter,value
package,express
repository,https://registry.npmjs.org
test_mode,false
version,4.18.2
filter,
output,output/express.html
```

| Параметр | Значение | Ошибки |
|---|---|---|
| `package` | имя анализируемого пакета npm, например `express` или `@types/node`; в тестовом режиме — большие латинские буквы | пустое имя, недопустимые символы, длиннее 214 символов, маленькие буквы в тестовом режиме |
| `repository` | URL реестра npm; в тестовом режиме — путь к файлу тестового репозитория | пустое значение, не http(s)-адрес, файла нет |
| `test_mode` | режим тестового репозитория: `true` или `false` | любое другое значение |
| `version` | точная версия пакета, например `4.18.2`; в тестовом режиме может быть пустой | пустая версия, версия не вида `1.2.3` |
| `filter` | подстрока: пакеты, в имени которых она есть, не учитываются; может быть пустой | пробелы внутри, подстрока исключает сам анализируемый пакет |
| `output` | необязательный: файл `.html` или `.mmd` для диаграммы; папки создаются сами | другое расширение, указана папка |

Ошибки самого файла: файла нет, файл пустой, неверный заголовок,
в строке не 2 столбца, неизвестный параметр, параметр повторяется,
не хватает параметров. Ошибки реестра: нет пакета, нет версии, нет связи,
ответ не JSON.

### Тестовый репозиторий

При `test_mode,true` параметр `repository` — путь к текстовому файлу.
Пакеты называются большими латинскими буквами. Версия не используется.

```text
# комментарий
A: B, C
B: D
C: D
D:
```

| Файл | Случай |
|---|---|
| `test_repos/simple.txt` | две прямые зависимости |
| `test_repos/diamond.txt` | ромб: общая зависимость раскрывается один раз |
| `test_repos/chain.txt` | длинная цепочка транзитивных зависимостей |
| `test_repos/cycle.txt` | два цикла |
| `test_repos/self_loop.txt` | пакет зависит сам от себя |
| `test_repos/filter.txt` | фильтр `XY` убирает ветки `XY` и `XYZ` |
| `test_repos/undescribed.txt` | зависимость не описана в файле |
| `test_repos/broken.txt` | ошибка формата |

Для каждого файла есть настройки `configs/test_*.csv`.

## 6. Сравнение со штатными инструментами npm

Штатный инструмент npm для просмотра зависимостей — `npm ls --all`:
он печатает дерево установленных пакетов. `src/npm_compare.py`
во временной папке выполняет настоящий `npm install` пакета,
читает `npm ls --all --json` и сравнивает вершины и рёбра.

Результаты (macOS, npm 11.13, ноябрь 2026):

| Пакет | Программа: пакеты, рёбра | npm: пакеты, рёбра | Совпадение |
|---|---|---|---|
| `express@4.18.2` | 68, 125 | 68, 125 | полное |
| `chalk@4.1.2` | 6, 5 | 6, 5 | полное |
| `axios@1.6.0` | 23, 34 | 23, 34 | полное |
| `chokidar@3.5.3` | 15, 17 | 15, 17 | полное на macOS |
| `react-dom@18.2.0` | 4, 4 | 5, 6 | npm добавил `react@18.3.1` |

Причины расхождений:

1. **Вид результата.** `npm ls` рисует дерево: пакет, который нужен
   нескольким пакетам, раскрывается один раз, а дальше помечается
   `deduped`. Программа строит граф: у такого пакета несколько входящих
   стрелок. Набор пакетов и рёбер при этом одинаковый.
2. **peerDependencies.** `react-dom` требует `react` как «соседа»
   (`peerDependencies`). npm начиная с версии 7 ставит такие пакеты
   сам, программа их не учитывает: это не зависимость пакета, а
   требование к проекту, в котором он используется.
3. **Платформа.** Необязательная зависимость `fsevents` у `chokidar`
   нужна только на macOS. На Windows и Linux npm её не ставит,
   а программа показывает её всегда: в реестре она записана в
   `dependencies`.
4. **Время.** Диапазон `^1.15.0` сегодня и через месяц может дать разные
   версии. npm и программа выбирают одинаково, если запущены в один день.
5. **Фильтр.** У npm нет фильтра по подстроке; сравнивать надо
   настройки без `filter`.
